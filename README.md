## 확정 저장

### 수동 — `✔ 폭염현황 확정`

그 시점의 기상현황·체감온도·폭염특보·입력내용 전체를 스냅샷으로 저장합니다.
**입력란의 값은 그대로 유지됩니다.** 몇 번을 눌러도 이력에 쌓이기만 합니다.

입력창을 열어둔 채로 확정을 눌러도 그 값이 먼저 저장된 뒤 스냅샷에 담깁니다.

### 자동 — 매일 한국시간 00:00

자정이 지나면 **전일자** 자료를 확정 스냅샷으로 남기고, **그 전일자의 입력란만** 비웁니다.
오늘 입력 중인 값은 절대 건드리지 않습니다.

- 확정자는 `자동(00시)` 로 기록됩니다.
- 자정에 아무도 화면을 켜두지 않았어도, 다음 접속 때 **최근 7일 중 밀린 날짜를 모두** 찾아 처리합니다.
- 여러 PC가 켜져 있어도 하루 한 번만 저장되도록 `/autofix/{날짜}` 에 표식을 먼저 남깁니다.
- 30초 주기로 감시합니다.
- **모든 날짜·시각 판단은 한국시간(KST) 고정**입니다. PC 시간대가 달라도 자정 기준이 어긋나지 않습니다.

> 이전 버전에서는 전일자 **목록만** 받아오고 내용은 읽지 않아,
> 새 브라우저로 접속하면 "저장할 내용이 없다"고 보고 조용히 건너뛰었습니다.
> 지금은 대상 일자의 내용을 공용 저장소에서 직접 읽어온 뒤 판단합니다.

### 이력 조회 · 삭제

`확정 이력` 에서 `보기` 를 누르면 **전 거점이 표로** 펼쳐집니다.
(기상·기온·체감·폭염특보·근로자·제품(시설)·운송 + 기타사항)

잘못 저장된 기록은 **사용자 코드 입력 상태에서 `삭제`** 로 지울 수 있습니다.
조회 전용에서는 삭제 버튼이 보이지 않고 우회 호출도 막힙니다. 삭제는 로그에 남습니다.

### 일괄 입력 · 일괄 삭제

거점 패널 제목 옆 두 버튼으로 30칸을 한 번에 처리합니다. (사용자 코드 입력 상태에서만 표시)

| 버튼 | 동작 |
|---|---|
| **전체입력 (특이사항 없음)** | 전 거점의 근로자 · 제품(시설) · 운송 칸을 `특이사항 없음` 으로 채움 |

- 실행 전 확인창이 뜨고, 이미 입력된 거점이 몇 개인지 알려줍니다.
- **기타사항은 전체입력 대상이 아닙니다.** 성격이 달라 일괄로 채우지 않습니다.
- 두 버튼 모두 복사 이미지에는 찍히지 않습니다.
- 실행 내역은 로그에 남습니다.

```json
    "logs":      { ".read": true, ".write": true },
    "confirmed": { ".read": true, ".write": true },

  }

```

`autofix` 가 없어도 자동확정은 동작하지만, 브라우저별로 각각 저장돼 중복될 수 있습니다.

## 새로고침이 안 되는 것처럼 보일 때

두 가지를 정리했습니다.

**① 캐시 제거** — 중계함수가 응답을 5분간 CDN에 캐시하고 있었습니다(`s-maxage=300`).
그 사이에는 새로고침을 눌러도 같은 응답이 돌아왔습니다. 이제 캐시를 완전히 끄고,
호출마다 `_t=타임스탬프` 를 붙여 중간 캐시를 우회합니다.

**② 관측시각을 함께 표시** — 초단기실황은 **매시 정시 관측이 약 40분 뒤 공개**됩니다.
즉 17:45 와 18:20 에 새로고침하면 둘 다 `17:00 관측값`이 나오는 게 정상입니다.
이게 "갱신이 안 된다"로 보이던 부분이라, 관측시각과 갱신시각을 나눠서 보여줍니다.

```
기상청 관측 17:00 · 갱신 18:20
```

관측시각이 그대로면 아직 새 관측이 공개되지 않은 것이고,
갱신시각이 바뀌면 조회는 정상적으로 이뤄진 것입니다.

# v4 — 날씨누리 1순위 · 기상청 API 예비 (build 2026-07-31.6-wnuri)

## 무엇이 바뀌었나

기온·습도·풍속·폭염특보를 **기상청 날씨누리 화면에서 직접** 읽어옵니다.
기존 격자 API는 예비 자료원으로 남아, 날씨누리가 실패한 거점만 자동으로 대체합니다.

| | 격자 API (기존) | 날씨누리 (신규 1순위) |
|---|---|---|
| 값의 성격 | 5km 격자 대푯값 | 날씨누리 화면과 동일한 실측값 |
| 갱신 주기 | 매시 정시 (1시간) | 10분 단위 |
| 폭염특보 | 통보문 파싱 (제외 표기·발효시각 직접 처리) | 문장으로 바로 수신 |
| 거점당 호출 | 2~3회 + 특보 별도 | 1회 |

체감온도 계산식은 그대로입니다. 날씨누리 기온·습도를 넣으면 날씨누리 표기값과
소수점까지 일치하는 것을 확인했습니다 (34.6℃ / 49% → 34.0℃, 날씨누리 표기 34.0℃).

## 자료 출처 표시

새로고침 버튼 바로 옆에 배지가 뜹니다.

- `● 날씨누리 15:50 · 전 거점` — 전부 날씨누리에서 받음
- `● 날씨누리 15:50 5곳 · 기상청 API 5곳` — 섞여 있음
- `● 기상청 API (격자) · 전 거점` — 날씨누리 전면 실패, 예비로 전환
- `● 샘플자료 (실시간 조회 실패)` — 둘 다 실패

## 조회 순서

```
① 날씨누리        ─ 기온 · 습도 · 풍속 · 체감온도. 성공한 거점은 격자 API 를 부르지 않는다.
② SKY 보완        ─ 날씨 아이콘만 격자에서
③ 기상청 격자 API  ─ ①이 실패한 거점만 (예비)
④ 폭염특보 통보문   ─ 전 거점. 폭염 단계는 자료원과 무관하게 항상 통보문이 기준.
```

**폭염 단계는 날씨누리 문장을 쓰지 않습니다.** 기상청 특보 통보문(`getWthrWrnMsg`)의
`t6`(현재 발효 현황)를 거점별 특보구역으로 대조해 판정합니다.
날씨누리 지역코드가 인접 시·군을 가리키더라도 폭염 단계는 지정한 구역 기준으로 맞습니다.

**체감온도는 날씨누리 표기값을 그대로 씁니다.** 우리 체감온도 공식으로 계산해도 결과는
같지만(실측 14건 대조, 오차 0.0℃), 표기값을 그대로 쓰면 홈페이지와 어긋날 여지가 없습니다.
날씨누리가 값을 못 줄 때만 공식으로 계산합니다.

## 파일

- `api/wnuri.js` — 날씨누리 중계함수. 태그를 모두 걷어낸 뒤 텍스트에서 값을 뽑습니다.
  마크업이 바뀌어도 문구만 남으면 파싱이 유지되도록 만들었습니다.
- `api/kma.js` — 기존 기상청 격자 API 중계함수 (예비 자료원).

## 주의

날씨누리는 **공식 API가 아닙니다.** 기상청이 예고 없이 주소나 화면 구조를 바꿀 수 있고,
장애 시 공지나 보상이 없습니다. 그래서 파싱이 실패하면 즉시 격자 API로 넘어가도록
이중화했고, 어느 쪽을 쓰고 있는지 화면에 항상 보이게 했습니다.

## 이전 버전에서 이어지는 수정 (2026-07-31)

- `vercel.json` — `/`, `/index.html`, `/version.json` 을 `no-store` 로 변경.
  기존에는 규칙이 `/index.html` 에만 걸려 있어 실제 접속 경로인 `/` 에 적용되지 않았습니다.
- `version.json` + 좌상단 빌드 번호 표시. 서버 빌드와 다르면 자동으로 한 번 다시 받습니다.
- 갱신 시각을 초 단위로 표시.
- 본사(서울)를 기상 조회 대상에서 제외 (주간예보 영역이 사라져 화면에 쓰이지 않음).

### 인증키 관련

`KMA_KEY` 환경변수 미등록이 새로고침 문제의 원인은 아니었습니다.
`api/kma.js` 에 예비 인증키가 들어 있어 환경변수 없이도 동작합니다.
다만 공개 리포에 키가 노출되므로, Vercel Settings → Environment Variables 에 `KMA_KEY` 를
등록하고 `FALLBACK_KEY` 를 빈 문자열로 바꾸는 것을 권장합니다.

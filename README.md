# 국내사업부 주요거점 폭염 현황판

한솔로지스틱스 국내사업부 10개 거점의 폭염 현황을 매일 14시 기준으로 취합하는 웹 현황판.

## 구성

| 파일 | 설명 |
|---|---|
| `index.html` | 현황판 전체 (단일 파일) |
| `api/kma.js` | 기상청 API 중계함수 (Vercel Serverless) |
| `vercel.json` | 배포 설정 |

## 왜 중계함수가 필요한가

공공데이터포털(`apis.data.go.kr`)은 CORS 헤더를 주지 않아 **브라우저가 직접 호출하면 차단**됩니다.
페이지를 어디에 올리든 마찬가지입니다. 서버가 대신 호출하는 방법뿐이며 그게 `api/kma.js` 입니다.

```
브라우저  →  /api/kma  →  apis.data.go.kr
             └ 서버끼리의 통신이라 CORS 미적용
```

## 배포

Vercel에서 이 리포지토리를 Import 하면 끝입니다. 빌드 설정 불필요(정적 + 서버리스 자동 인식).

**권장**: Settings → Environment Variables 에 `KMA_KEY` 를 등록하세요.
등록하지 않으면 `api/kma.js` 안의 기본값이 쓰입니다.

## 데이터 저장

Firebase Realtime Database (`weather-5eb52`, asia-southeast1).

```
/days/{YYYY-MM-DD}/wx/{거점}       14시 기준 기상현황·체감온도·폭염특보
/days/{YYYY-MM-DD}/notes/{거점}    근로자 / 제품(시설) / 운송 특이사항
/days/{YYYY-MM-DD}/etc             기타사항 (국내사업부장)
/logs/{자동ID}                     입력 이력
```

거점 담당자가 입력하면 즉시 저장되고, 다른 거점 화면에 **20초 안에 자동 반영**됩니다.
연결이 끊기면 브라우저에만 저장하고 상단에 "공용 저장소 끊김"이 표시됩니다.

### ⚠ 보안 규칙 (반드시 확인)

Firebase 콘솔 → Realtime Database → **규칙** 에 아래를 붙여넣고 **게시**하세요.

```json
{
  "rules": {
    "days":  { ".read": true, ".write": true },
    "logs":  { ".read": true, ".write": true },
    "users": { ".read": true, ".write": true },
    "sites": { ".read": true, ".write": true }
  }
}
```

`users` / `sites` 가 빠지면 **사용자 관리·거점 관리가 401 Permission denied** 로 막힙니다.
(이전 버전 안내에 이 두 경로가 없어 실제로 문제가 됐습니다)

권한 오류가 나면 상단바에 `● 저장소 권한 오류` 가 뜨고, 클릭하면 붙여넣을 규칙이 표시됩니다.

> 이 규칙은 주소를 아는 사람 누구나 읽고 쓸 수 있는 상태입니다.
> 더 잠그려면 Firebase 익명 인증을 켜고 `".write": "auth != null"` 로 바꾸세요.
> 테스트 모드 규칙은 30일 뒤 만료되지만, 위 규칙은 만료되지 않습니다.

## 관리 페이지 (최고관리자 전용)

`skingws` 로 접속하면 상단바에 **⚙ 관리 페이지** 가 나타납니다. 탭 두 개로 구성됩니다.

### 사용자 관리

소속·이름·권한으로 추가 / 수정 / 삭제. 같은 소속 동명이인은 중복 등록되지 않습니다.

| 권한 | 입력 범위 |
|---|---|
| 일반사용자 | 자기 거점 열의 근로자 / 제품(시설) / 운송 |
| 일반사용자 (소속 = 국내사업부장) | 표 하단 기타사항 |
| 관리자 | 표 전체 (로그·관리 페이지 접근 불가) |

### 거점 · 주소 관리

거점명, 주소, 위도·경도, 기상청 격자(nx·ny), 특보 시·군명, 발표관서를 편집합니다.

**주소를 넣고 `주소로 좌표 찾기`** 를 누르면 위경도와 격자가 자동으로 채워집니다.
후보가 여러 개면 목록에서 골라 적용할 수 있습니다. (배포된 주소에서만 동작 — `/api/geo` 사용)

- **특보 시·군명** : 기상청 특보 통보문에 쓰이는 이름 (장항 → `서천`, 부산신항 → `부산`)
- 관리 페이지에 처음 들어가면 내장 기본값 10개소가 공용 저장소에 자동 등록됩니다.
- **거점을 추가·삭제하면 폭염 현황표의 열이 바뀝니다.** 확인 후 진행하세요.

## 갱신 · 일자 마감

**새로고침 버튼(제목 아래, 빨간색 하나)** 을 누르면
날씨를 다시 받아와 각 거점의 기상현황·체감온도·폭염특보를 갱신하고,
표 최상단의 기준일자·시간을 **누른 시점**으로 바꿉니다. (`2026년 7월 29일 (수) 19시 32분 기준`)
처리 중에는 버튼이 `로딩중... 1.3초` 처럼 경과시간을 표시하고 화면이 잠시 흐려집니다.
**로그인하면 자동으로 한 번 갱신**되고, 이후 10분마다 조용히 자동 갱신됩니다.

**매일 자정(00:00)** 이 되면 사용자가 아무것도 하지 않아도
전날 표가 공용 저장소에 그대로 확정 저장되고(날짜 드롭다운으로 열람),
오늘자 표가 빈 상태로 새로 준비됩니다.

- **체감온도** — 기상청 여름철 산출식(2020 개정, 습구온도 기반). 10~4월은 풍속냉각지수.
- **폭염특보** — 기상특보 통보문 `t6` 의 구역 표기를 거점에 매칭.
  `충청남도(부여, 청양, 태안 제외)` 같은 **"제외" 표기**와
  `부산(부산동부 제외)` 처럼 광역명이 하위구역명에 포함되는 경우까지 처리합니다.


## 기온·체감온도가 날씨누리와 다르게 보일 때

**계산식은 정확합니다.** 날씨누리 「도시별관측」의 기상청 공식 체감온도와
24개 관측소를 대조한 결과 **전부 소수점 1자리까지 일치**했습니다. (평균오차 0.00℃)

| 지점 | 기온 | 습도 | 기상청 발표 | 현황판 계산 |
|---|---|---|---|---|
| 대전 | 26.4℃ | 83% | 28.6℃ | 28.6℃ |
| 군산 | 26.9℃ | 91% | 29.7℃ | 29.7℃ |
| 천안 | 25.5℃ | 97% | 28.7℃ | 28.7℃ |
| 부산 | 29.7℃ | 57% | 29.9℃ | 29.9℃ |
| 북부산 | 30.5℃ | 67% | 31.5℃ | 31.5℃ |

차이가 나는 이유는 **어느 지점의 기온을 쓰는가**입니다.

| | 현황판 | 날씨누리 「도시별관측」 |
|---|---|---|
| 자료 | 초단기실황 — 관측을 5km 격자로 분석한 값 | 관측소(ASOS) 실측값 |
| 위치 | **사업장 주소의 격자** | 대표 관측소 위치 |

관측소는 사업장에서 꽤 떨어져 있습니다.

| 거점 | 현황판 (사업장) | 가까운 관측소 | 거리 |
|---|---|---|---|
| 대전 (대덕구 문평동) | 27.3℃ / 체감 29.1℃ | 대전 관측소(유성구) 26.4℃ / 28.6℃ | 약 8km |
| 천안 (동남구 광덕면) | 26.0℃ / 체감 28.4℃ | 천안 관측소(시내) 25.5℃ / 28.7℃ | 약 20km |
| 부산신항 (강서구 명지) | 30.0℃ / 체감 30.5℃ | 부산 관측소(중구) 29.7℃ / 29.9℃ | 약 18km |

*(2026-07-30 08:00 실측 대조)*

즉 **양쪽 모두 기상청 자료이고 계산식도 같으며, 가리키는 지점이 다릅니다.**
사업장 현황판으로는 사업장 위치의 격자값이 더 맞습니다.

날씨누리에서 **주소(읍면동)로 검색**해 나오는 동네예보 화면은 현황판과 같은 격자자료를 쓰므로
값이 일치합니다. 「도시별관측」 표와 비교하시면 위와 같은 차이가 납니다.

> 갱신 지연도 줄였습니다. 초단기실황은 정시 관측이 약 40분 뒤 공개되는데,
> 최신 시각부터 1시간씩 뒤로 물러가며 자료가 있는 것을 찾도록 바꿨습니다.

## 폭염특보 — 발효시각 처리

통보문에는 **발표시각(tmFc)** 과 **발효시각(t5)** 이 따로 있고, 다를 수 있습니다.

```
7/29 16:00 발표  →  7/30 11:00 발효   (부산 폭염중대경보)
7/29 10:00 발표  →  7/29 11:00 발효   (부산 폭염경보)
```

발표시각만 보고 최신 통보문을 고르면 **아직 오지 않은 특보를 현재 상태로 표시**합니다.
그래서 **발효시각이 이미 지난 통보문 중 가장 나중에 발효된 것**을 채택합니다.

아직 발효되지 않은 변경은 표에 넣지 않고, 화면에 별도로 안내합니다.

```
🕐 발효 예정  부산신항 경보→중대경보 (7/30 11:00)
```

### 로딩 속도

기상청 호출을 **1회 갱신당 약 86건 → 25건**으로 줄였습니다.

| 개선 | 내용 |
|---|---|
| 중기예보 제거 | 거점별 2건 × 9행 = 18건 삭감 |
| 하늘상태 통합 | 단기예보 응답에서 추출, 별도 호출 11건 삭감 |
| 실황 기준시각 공유 | 한 번 찾은 시각을 전 거점이 재사용 (재시도 반복 제거) |
| 특보 병렬 조회 | 관서 4곳을 순차 → 동시 |

> 본사는 주간예보와 특보 표시에만 나오고, **폭염 현황표의 거점 열에는 들어가지 않습니다.**
> (첨부 엑셀 양식 그대로 10개 거점 유지)

중기예보 필드번호는 '발표일로부터 몇 일째'이고 오늘이 1일째라서 `taMin4` 가 D+3 입니다.
(`taMin3` 은 응답에 없음) 이 매핑을 잘못 잡으면 D+3 이 빈칸으로 남습니다.

| 거점 | 중기 육상구역 | 중기 기온지점 |
|---|---|---|
| 본사(서울) | 11B00000 서울·경기 | 11B10101 서울 |
| 군산 / 군산 CY | 11F10000 전북 | 11F10501 군산 |
| 장항 | 11C20000 대전·충남 | 11C20201 보령 |
| 대전 / 신탄진 / 신탄진 CY | 11C20000 | 11C20401 대전 |
| 천안 | 11C20000 | 11C20101 천안 |
| 아산 CY | 11C20000 | 11C20301 아산 |
| 부산신항 | 11H20000 부산·경남 | 11H20201 부산 |
| 의왕 | 11B00000 서울·경기 | 11B20601 수원 |

장항(서천)과 의왕은 중기 기온지점이 따로 없어 가장 가까운 보령·수원을 씁니다.

**지오코딩 정확도** — 대전·신탄진·부산신항·의왕은 번지까지 정확히 매칭됐습니다.

격자 한 칸이 5km라 실측에 큰 영향은 없지만, 더 정확히 맞추려면
`SITES` 의 `lat`/`lon`/`nx`/`ny` 를 수정하면 됩니다.

거점 추가·수정은 `index.html` 의 `SITES` 배열만 고치면 됩니다.
